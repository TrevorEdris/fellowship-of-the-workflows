## Scan Results

### Claude / Anthropic

**Claude Code v2.1.89 (April 1)**
- Added `"defer"` permission decision to PreToolUse hooks — hooks can now defer a decision back to Claude rather than block or allow.
- Added `PermissionDenied` hook event fired after auto-mode denials.

**Claude Code v2.1.91 (April 2)**
- **Conditional `if` field for hooks** — hooks config now supports an `if` expression to gate execution.
- MCP tool result persistence via `_meta["anthropic/maxResultSizeChars"]` (up to 500K chars).
- Plugins can ship executables under `bin/`.

**Claude Code v2.1.94 (April 7)**
- Default effort changed to `high` for Pro/Max users on Opus/Sonnet 4.6.

**Claude Code v2.1.98 (April 9)**
- Added subprocess sandboxing with PID isolation on Linux.
- Monitor tool for streaming events added.
- Fixed Bash permission bypass vulnerabilities.

**Claude Code v2.1.105 (April 13)**
- **PreCompact hook support** officially added (the `context-snapshot.js` hook in this repo already uses this event).
- Added `path` parameter to EnterWorktree tool.
- Background monitor support for plugins.

**Claude Code v2.1.108 (April 14)**
- Added `ENABLE_PROMPT_CACHING_1H` env var for 1-hour prompt cache TTL (default is 5 min).
- Added recap feature — context summary when returning to a session.
- Model can now discover and invoke built-in slash commands via Skill tool.

**Claude Code v2.1.111 (April 16) — Major**
- **Claude Opus 4.7 (`claude-opus-4-7`) with `xhigh` effort level** now available.
- Auto mode available for Max subscribers on Opus 4.7.
- `/effort` interactive slider added.
- **`/ultrareview` skill** (and `claude ultrareview [target]` CLI subcommand) for cloud-based code review.
- `/less-permission-prompts` built-in skill added.
- Windows: PowerShell tool rolling out.

**Claude Code v2.1.113 (April 17)**
- CLI now spawns native binary instead of bundled JavaScript — faster startup.
- Added `sandbox.network.deniedDomains` to block specific domains.
- Subagents that stall fail with clear error after 10 minutes.
- Improved `/loop`: Esc cancels pending wakeups.

**Claude Code v2.1.116 (April 20)**
- `/resume` on large sessions 67% faster (up to 40MB+ sessions).

**Claude Code v2.1.118 (April 23)**
- **Hooks can invoke MCP tools directly via `type: "mcp_tool"`** — new hook action type alongside `type: "command"`.
- Vim visual mode (`v`/`V`) added.
- Merged `/cost` and `/stats` into `/usage`.
- WSL can inherit Windows-side managed settings.

**Claude Code v2.1.120 (April 28)**
- **`claude ultrareview [target]`** CLI subcommand for non-interactive cloud code review.
- Skills can reference effort level with `${CLAUDE_EFFORT}`.
- `AI_AGENT` env var now set for subprocesses.
- Windows: Git for Windows no longer required.

**Claude Code v2.1.121 (April 28)**
- **PostToolUse hooks can now replace tool output for all tools** — hooks can intercept and rewrite what a tool returns.
- Added `alwaysLoad` option to MCP server config.
- `claude plugin prune` to remove orphaned dependencies.
- Type-to-filter search box added to `/skills`.

**Claude Code v2.1.126 (May 1)**
- `claude project purge [path]` — delete all Claude Code state for a project.
- Model picker lists models from gateway `/v1/models` endpoint.
- `--dangerously-skip-permissions` now bypasses protected paths.
- Fixed clipboard writes exposing content to EDR/SIEM telemetry (security fix).

### Assessment 1: PostToolUse Hook Output Replacement

```
### New Feature: PostToolUse hooks can replace tool output
- **Tool:** Claude Code
- **Date:** 2026-04-28 (v2.1.121)
- **Release stage:** stable
- **What changed:** PostToolUse hooks can now return a replacement value for any tool's output,
  letting hooks filter, redact, or transform what Claude sees after a tool runs.
- **Project impact:**
  - [x] Existing workflow update? Which: hooks/protect-secrets.js, hooks/context-snapshot.js
  - [ ] New workflow needed?
  - [ ] Configuration change needed?
- **Recommendation:** Evaluate whether protect-secrets.js should run as PostToolUse to redact
  secrets from tool output (e.g., Read returning a file with credentials). Currently it only
  blocks commands pre-execution.
- **Priority:** medium
- **Affected files:** hooks/protect-secrets.js, hooks/block-dangerous-commands.js
```
